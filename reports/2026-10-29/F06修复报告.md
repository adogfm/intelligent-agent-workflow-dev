# F06：39 条 pytest 收集警告归因与处理

日期：2026-10-29（Asia/Shanghai）。状态：已消除，完整验证无警告，测试数量保持不变。

## 原因分析

39 条均为 `PytestCollectionWarning`：pytest 在符合文件命名规则的模块中，看到了名称以 `Test` 开头、但带有构造函数的非测试类。这些类型是业务模型、Protocol、测试执行器和 Agent；同一类型在不同模块中重复暴露，因此产生多条提示，并非 39 个测试方法无法运行。

| 收集来源 | 原警告数 | 原因 |
|---|---:|---|
| 根目录 `test_agent.py` | 6 | 业务模块及其导入对象被当作测试候选 |
| 根目录 `test_feedback.py` | 4 | 同上 |
| `tests/test_failure_feedback.py` | 5 | 导入的非测试类使用 Test* 原名 |
| `tests/test_fix_agent.py` | 5 | 同上 |
| `tests/test_fix_syntax_retries.py` | 4 | 同上 |
| `tests/test_repair_loop.py` | 5 | 同上 |
| `tests/test_review_policy.py` | 5 | 同上 |
| `tests/test_test_agent.py` | 4 | 同上 |
| `tests/test_workflow.py` | 1 | 同上 |
| 合计 | 39 | 业务文件误发现 10 条，测试模块导入歧义 29 条 |

涉及 8 个业务类型：TestGenerator、TestCase、TestExecutionResult、TestGenerationResult、TestRunner、TestAgent、TestExpectation、TestFailure。修复前所有真实测试都已位于 `tests/`，共 261 个测试 node ID。

## 统一处理

1. 在 `pyproject.toml` 中设置 `testpaths = ["tests"]`，明确默认测试目录。根目录的 test_agent、test_feedback、test_worker 是业务模块，没有实际测试用例被移除。
2. 在上述 7 个测试文件中，为非测试对象增加导入别名，并更新相应引用：TestCase → GeneratedCase、TestExecutionResult → ExecutionResult、TestFailure → FailureDetail、TestGenerationResult → GenerationResult、TestAgent → WorkflowTestAgent、TestRunner → SubprocessTestRunner。
3. 保留公开业务 API、真实测试类、测试方法、unittest.TestCase 基类和 mock 目标路径。没有向业务类添加 pytest 专用标记，也没有缩窄 python_classes/python_files 模式。
4. CI 的 Linux 作业安装 `.[test]` 后新增严格收集检查：`python -m pytest --collect-only -q -W error::pytest.PytestCollectionWarning`。新增收集警告会导致失败，现有 unittest 执行步骤继续保留。

没有添加全局 `ignore`、`filterwarnings` 屏蔽规则，也没有使用 `--disable-warnings` 进行本次验收。`-W error` 是把收集警告提升为错误，而非隐藏警告。

`testpaths` 定义默认发现边界；本次验证默认命令与显式指定 `tests/` 两种正常测试入口，不将显式要求 pytest 收集业务文件的命令视为项目测试入口。

## 验证结果

- 修复前：261 个测试 node ID、39 条收集警告。
- 修复后默认发现与显式 `tests/` 发现：均保留完全相同且顺序一致的 261 个 node ID，收集警告为 0。
- 完整运行：**261 项测试、847 个子测试全部通过，无警告**，耗时 97.61 秒。与 F04 验收时的方法数和子测试数一致。
- 标准库 unittest 发现：仍为 261 个测试方法。
- 独立 `.venv` 的 `pip check`：无依赖冲突；`git diff --check` 通过。

完整测试使用以下严格命令执行，未禁用警告输出：

```powershell
.\.venv\Scripts\python.exe -m pytest -q -W error::pytest.PytestCollectionWarning
```

只检查测试发现可使用：

```powershell
.\.venv\Scripts\python.exe -m pytest --collect-only -q -W error::pytest.PytestCollectionWarning
.\.venv\Scripts\python.exe -m pytest tests --collect-only -q -W error::pytest.PytestCollectionWarning
```

CI 新增命令已在本地验证通过，未推送或触发远程 CI。本次完整运行在获准的沙箱外执行，以免 Windows 沙箱临时目录权限干扰测试子进程。
