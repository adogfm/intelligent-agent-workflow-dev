# F03：初始代码编译校验漏检修复

日期：2026-10-29（Asia/Shanghai）。状态：已修复并通过开发版独立 `.venv` 验证。

## 修复结果

初始生成模型和 CodeChecker 现在会拒绝能够通过 AST 解析、但无法通过 Python 编译的代码，包括：

| 样本 | 处理结果 |
|---|---|
| 函数外 `return` | 拒绝生成结果；静态检查报告 HIGH syntax-error |
| 循环外 `break` / `continue` | 同上 |
| 函数外 `await` / `yield` | 同上 |
| `nonlocal` 没有外层绑定 | 同上 |
| 函数参数重名 | 同上 |
| `from __future__` 位置不合法 | 同上 |

合法作用域内的 return、break、continue、await、yield、nonlocal 和显式 future import 保持可用。校验只进行解析和编译，不导入或执行待检代码，也不保证业务或运行时正确性。

## 实现

- `models.py`：`CodeGenerationResult` 在 `ast.parse()` 后增加 `compile(tree, 'generated_code.py', 'exec', dont_inherit=True)`。编译错误沿用 `GeneratedCodeSyntaxError`，保留原代码及错误原因，模型解析器进一步映射为 `LLMCodeSyntaxError`。
- `code_checker.py`：访问规则 AST 前增加编译检查。解析或编译产生的 SyntaxError 都转换为原有 `syntax-error` 规则，保留行号和 HIGH 级别。
- `coding_agent.py`：将供应商调用与结果复验纳入统一校验错误处理；无效结果、事后修改的模型，以及供应商内部构造模型时产生的语法错误，均以结构化生成错误上报。已有代码、已有报告和业务状态版本保持不变，后续审查不会执行。
- 初始生成仍在失败时停止，不新增自动重试。原有 Fix Agent 语法重试机制保持有效；其绕过模型校验的编译错误用例已调整为显式 `model_construct()`，继续验证防御校验与重试。
- README、Design.md 和问题报告同步更新。

`dont_inherit=True` 用于避免校验模块本身的 future 编译标志干扰待检代码，代码自身显式声明的 future 特性仍由 Python 编译器处理。
